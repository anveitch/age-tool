**Test release.** This is a release candidate for age-tool 2.1, for testers. Please report anything that goes wrong or is confusing; see the end of these notes.

## What's new in 2.1

- **Encrypt with a password instead of a key**, in the desktop app and the command-line tool. Handy for sending a file to someone who doesn't use age-tool: they only need the password. No key of your own is needed. Files are standard age password files, interchangeable with `age -p`.
- **Password rule:** at least 8 characters, including a number and a special character. Easy-to-guess passwords such as `Summer26!` are refused. Organisations can make the rule stricter in `settings.json`, but not weaker.
- **Suggested passwords:** four random words, a number and a special character, e.g. `plank-trade-mule-lure-19!`. Easy to remember, hard to guess.
- **Saved passwords:** after encrypting with a password, you choose whether to keep a record of it. Records are locked with your own key, so you can look a password up later with your key's passphrase (desktop app: **My keys > Saved passwords**; command line: **Key Management > Saved Passwords**). Or don't save it, and the password is shown once to write down.
- **Decrypting** recognises password files by itself and asks for the password instead of a key.
- **Quit button** on the desktop app's home screen.
- The desktop app's window is a little taller, so everything fits.

The [user guide](https://github.com/anveitch/age-tool/blob/v2.1.0-rc.1/docs/user-guide.md) has a new section on passwords, with screenshots.

**A password is weaker than a key:** anyone who gets the file can try to guess its password. Use a long or suggested password, and tell people the password a different way from the file (for example, by phone).

**Command line:** Key Management gains **8) Saved Passwords**, and **Back** moves to 9.

## Downloads

| You have | Download |
|---|---|
| Linux PC or laptop (desktop app) | `age-tool-linux-x64.AppImage` |
| Linux on ARM, e.g. Raspberry Pi (desktop app) | `age-tool-linux-arm64.AppImage` |
| macOS, Apple Silicon (command line) | `age-tool-macos-arm64` |
| macOS, Intel (command line) | `age-tool-macos-intel` |
| Linux (command line) | `age-tool-linux-x64` or `age-tool-linux-arm64` |
| Windows (command line) | `age-tool-windows-x64.exe` |

**Desktop app:** download the AppImage, make it executable (in Files, right-click → **Properties** → **Executable as Program**), then double-click it. If you already use 2.0, replace the old file and open the new one; your keys stay where they are.

**Check your download** (optional): put `SHA256SUMS` in the same folder and run `sha256sum -c SHA256SUMS --ignore-missing` (Linux) or `shasum -a 256 -c SHA256SUMS --ignore-missing` (macOS). Your file should say `OK`.

Homebrew stays on 2.0.0 until 2.1.0 is released.

## What to test

- Encrypt a file with a password (your own, and a suggested one), keep a record, then decrypt it.
- Find the password again under Saved passwords.
- Try a weak password, and check the message says what to change.
- Open a password file made by `age -p` with age-tool, or the other way round.

## Reporting problems

[Open an issue](https://github.com/anveitch/age-tool/issues) with your system (e.g. Ubuntu 24.04, GNOME), and what you did, what you expected, and what happened. Never include a passphrase, a file password or a private key (`AGE-SECRET-KEY…`) in a report.
